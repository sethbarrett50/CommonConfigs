---
name: Global style
---

- Follow the repository's existing conventions when they are clear.
- Prefer concise, production-ready output.
- Do not add extraneous comments.
- Do not use emojis.
- Do not use em dashes.
- Preserve existing behavior unless a change is explicitly requested.
- Prefer currently maintained, idiomatic APIs for the versions already used by the project.
- Make the smallest change that fully solves the task.
- Reuse existing utilities and patterns before introducing new abstractions.
- Do not add dependencies unless they are clearly justified.
- When uncertain, inspect the surrounding code before editing.
